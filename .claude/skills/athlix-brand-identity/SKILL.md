## Typography
- Logo Latin wordmark only: "Good Timing W00 Light" (never for body text).
- English text (headings + body): **Poppins**, weights ExtraLight–ExtraBold.
- Arabic text (headings + body): **FrutigerLT Arabic** — approved 12 Aug 2026, replacing Alinma Display everywhere. Three approved weights, mapped as follows:
  - **FrutigerLT Arabic 45 Light** → light/secondary text
  - **FrutigerLT Arabic 55 Roman** → body/regular text
  - **FrutigerLT Arabic 65 Bold** → headings/emphasis
- FrutigerLT Arabic is a commercially licensed font (Monotype/Linotype). If it is unavailable in the current design environment, **disclose this immediately and ask Ali before substituting anything** — no open-source fallback has been approved yet. Never fall back to Arial/Times New Roman/system defaults for Arabic silently.
- Alinma Display and Tajawal are both retired. If either appears in an existing Athlix file, flag it as a pending font-sweep item.

## Application patterns (learned from the 40-page guide's real collateral)
- Dark/formal collateral (business cards, letterhead, signage, press backdrop, gift packaging): Powerful or Astronaut Blue field, white/light-gradient logo, Light Baby Blue for secondary text.
- App UI / dashboards: white background, Blue Spectrum for chrome (sidebar, buttons, headers), Light Baby Blue tint panels. Even semantic status labels ("Excellent", "Very Good") stay inside the blue family rather than using red/amber/green traffic-light colors — this preserves the "trust" tone.
- Social/marketing tiles: bold Light Blue background, black or white display type.
- Merchandise (polo, bag, bottle, scarf): two-tone Astronaut Blue + Light Baby Blue system only.
- Never mix in off-brand accent hues (no red/orange/purple/teal-green) anywhere, even for charts, risk callouts, or category coding — differentiate using tints/shades of the 13 approved colors instead (e.g. Blue Spectrum vs. Astronaut Blue vs. Morpho Blue vs. Dark Cobalt vs. Nickel for a multi-category chart, not arbitrary rainbow colors).
- Prefer subtle linear gradients (within the approved palette, e.g. Powerful → Astronaut Blue → Blue Spectrum) over flat single-color fills for headers/hero bands and category cards in detailed, information-dense designs — this matches the brand guide's own "fluid, calculated gradient system" language and reads as more premium than flat recoloring.

## MANDATORY: Arabic .pptx files must be produced as true RTL, not just visually-correct

When generating or editing a `.pptx` that contains Arabic text — via python-pptx or any direct OOXML/XML manipulation — **always set `rtl="1"` on the `<a:pPr>` element of every Arabic paragraph**, and set `lang="ar-SA"` on every `<a:rPr>` / `<a:endParaRPr>` run-properties element (not the `en-US` default).

Why this matters: a file missing `pPr/@rtl="1"` still *displays* correctly in PowerPoint's normal read/view mode, because Windows' Uniscribe/DirectWrite bidi algorithm auto-detects Arabic and renders it right-to-left regardless of the flag. This makes the bug invisible during a quick visual QA pass. But the moment a user **clicks into the text box to edit it**, PowerPoint's editing/text-layout engine relies on the explicit `rtl` flag rather than bidi auto-detection, and without it the Arabic glyphs render as corrupted, overlapping, randomized-looking symbols — the file looks broken and becomes effectively uneditable for the client.

Practical implementation (python-pptx + lxml), applied to every `<a:p>` inside every shape's text frame:
```python
from pptx.oxml.ns import qn
for p in txBody.findall(qn('a:p')):
    pPr = p.find(qn('a:pPr'))
    if pPr is None:
        pPr = p.makeelement(qn('a:pPr'), {})
        p.insert(0, pPr)
    pPr.set('rtl', '1')
    for rPr in p.findall(f'.//{qn("a:rPr")}') + p.findall(qn('a:endParaRPr')):
        rPr.set('lang', 'ar-SA')
```

This is not optional or file-specific — treat it as a required step in the production/QA checklist for **every** Arabic Athlix deliverable (and any other Arabic PPTX work), alongside the color and font checks above, before the file is ever handed to the user.
